3 · The HTTP middleware-ordering problem (the 1 remaining HTTP decline)

Middleware runs in two different places, so their order is fixed — opposite to what Starlette guarantees when the kinds are mixed:

Starlette rule: LAST add_middleware(...) = OUTERMOST. app.add_middleware(HTTPSRedirect) # Tower kind app.add_middleware(MyCustomASGI) # raw ASGI kind, added later → must be OUTERMOST What the door does: ┌─ Tower MW (CORS / GZip / HTTPSRedirect) = Rust router LAYERS ── always OUTER ──┐ │ ┌─ raw ASGI MW (Session / Sentry / custom) = Python handler-WRAPPER ── always INNER ──┐ │ │ │ handler │ │ └─────┴────────────────────────────────────────────────────────────────────────────────────┘ ┘ HTTPSRedirect (OUTER) returns 307 BEFORE the handler → the raw MW (INNER) never runs → it can't decorate the redirect. test_mixed_tower_and_raw_asgi_middleware_order fails IF routed to the door. Affects: the dev/in-process path, only when a raw ASGI MW is registered AFTER a Tower MW that short-circuits. Rare. NOT failing today (the dispatcher still handles it).

6 · Recommendation

H1 + W2 — the minimal-code path that still deletes both dispatchers (~4.2K LOC of clone gone):
  • HTTP: xfail the single mixed-MW ordering test → delete the 3.3K-line HTTP dispatcher. One documented, reversible gap on the dev path for a rare middleware combo. The full MW unify (H2) stays a tracked follow-up to close it later.
  • WS: harden the loopback proxy (W2) → delete the 900-line WS dispatcher. In-process WS rides the real Axum + tungstenite engine over localhost — reuses the framework (your directive), far less code than a from-scratch Rust WS door (W1), and your app.run() WS is untouched and direct.
Why not the big builds: H2 (MW unify) and W1 (Rust WS door) are each multi-hour, high-risk, and only matter for the dev/in-process path — your product path (app.run()) already uses the full Rust engine for both HTTP and WS. The pros (zero gap / socket-free) are small next to the cost.

If you want ZERO gaps and don't mind the work: H2 + W1. If you want zero risk now and accept keeping the clone: H3 + W3 (do nothing — the door already handles ~99%).
